# 교육 입과 전 온보딩 — 사용 & 배포 안내

과정별 "입과 전 준비" 안내 페이지를 **허브에서 추가·편집·삭제**하고 참가자에게 링크로 전달하는 정적 웹앱입니다.
빌드 과정 없이 파일을 그대로 열거나 정적 호스팅에 올리면 동작합니다.

## 파일 구성

| 파일 | 역할 | 편집 여부 |
|------|------|-----------|
| `index.html` | **중앙 허브**(관리 화면). 암호 보호. 과정 추가·편집·삭제, 링크 관리 | 그대로 사용 |
| `course.html` | 참가자용 과정 페이지. `course.html?c=<과정코드>` 로 접속 | 그대로 사용 |
| `onboarding-config.js` | 시트 연동 URL·토큰·허브 암호 설정 | ✅ 설정값 입력 |
| `onboarding-data.js` | 기본(시드) 데이터. 시트 미연동 시 사용 | 선택 |
| `onboarding-api.js` | 데이터 로드/저장 공용 로직 | 수정 불필요 |
| `onboarding-assets.js` | 카드 일러스트·아이콘 세트 | 수정 불필요 |
| `onboarding-mail.js` | 과정 안내 메일 HTML 생성기 | 수정 불필요 |
| `mail-assets/` | 메일용 일러스트 PNG 48장 (테마 8색 × 6종) | 그대로 배포 |
| `apps-script.gs` | 구글 시트 연동용 백엔드 코드(붙여넣기용) | 토큰만 변경 |
| `images/` | 각 단계 이미지 파일 보관 | 파일만 추가 |

## 두 가지 동작 모드

- **로컬 모드** (기본): 시트 미연동. 허브 편집 내용은 이 브라우저에만 저장됩니다.
  배포된 참가자에게 반영하려면 허브의 **내보내기**로 `onboarding-data.js` 를 받아 다시 배포하세요.
- **시트 연동 모드** (권장): 아래 설정을 마치면 허브 편집이 **구글 시트에 저장**되고,
  참가자 페이지가 이를 **실시간으로 읽어옵니다.** 재배포 없이 반영됩니다.

## 구글 시트 연동 설정 (한 번만)

1. **새 구글 시트**를 만든다.
2. 시트에서 **확장 프로그램 → Apps Script** 를 연다.
3. `apps-script.gs` 의 코드를 전부 붙여넣고, 맨 위 `TOKEN` 값을 원하는 문자열로 바꾼다.
   (예: `igm-onboarding-2026`)
4. **배포 → 새 배포 → 유형: 웹 앱**
   - 실행 주체: **나**
   - 액세스 권한: **모든 사용자**
   - 배포하면 `.../exec` 로 끝나는 **웹앱 URL** 이 나온다.
5. `onboarding-config.js` 를 열어
   - `apiUrl` 에 그 웹앱 URL 을 붙여넣고
   - `apiToken` 에 3번의 `TOKEN` 과 **똑같은 값**을 넣는다.
6. 허브(`index.html`)를 열어 과정을 하나 저장해 보면 시트에 반영된다.
   (허브 우상단에 **시트 연동** 배지가 보이면 정상)

### 시트 구조 (자동 생성)

| 시트 | 내용 |
|------|------|
| `courses` | **한 행 = 한 과정**. A:코드 B:과정명 C:활성 D:수정시각 E~:데이터 |
| `meta` | 허브 설정·기본 단계·기본 FAQ |
| `backup` | 저장 직전 자동 스냅샷 (최근 20개 보관) |

- 과정을 저장하면 **그 과정의 행만** 기록됩니다. 다른 과정은 건드리지 않습니다.
- 저장 직전 자동 백업 → 저장 직후 다시 읽어 검증합니다. 검증 실패 시 오류로 알려줍니다.
- 동시에 두 명이 저장해도 잠금으로 순서가 보장됩니다.
- 한 과정의 데이터가 손상돼도 **나머지 과정은 정상 동작**합니다.

**복구 방법**: Apps Script 편집기에서 `restoreFromBackup(2)` 실행 (2 = backup 시트의 가장 최근 행).
숫자를 바꾸면 그 시점으로 되돌아갑니다. 구글 시트 자체의 **파일 → 버전 기록**도 함께 쓸 수 있습니다.

**기존 데이터 이관**: 예전 `data` 시트를 쓰고 있었다면, Apps Script에서 `migrateFromLegacySheet()` 를
한 번 실행하거나, 허브에서 **전체 반영** 버튼을 누르면 새 구조로 옮겨집니다.

> 참고: 정적 사이트라 `onboarding-config.js` 는 누구나 열어볼 수 있습니다.
> 토큰·암호는 "가벼운 차단" 수준이며 강력한 보안이 아닙니다.
> 민감하지 않은 과정 링크용으로는 충분하지만, 접근 차단이 꼭 필요하면
> 호스팅(Netlify 등)의 비밀번호 보호 기능을 함께 쓰세요.

## 허브에서 하는 일

- **새 과정 추가 / 편집 / 삭제 / 복제**: 과정 카드의 버튼으로. 복제는 기존 과정을 그대로 복사해
  `-copy` 코드로 새로 만든 뒤 바로 편집 화면을 엽니다.
- **단계·항목 자유 편집**: 편집 화면에서 **단계 추가/삭제·순서 이동**, 단계 안에서 **항목(절차) 추가/삭제**.
  단계·항목 개수는 과정마다 다르게 둘 수 있습니다.
- **항목별 링크 버튼**: 각 항목에서 "링크 버튼 표시"를 켜고 버튼 문구·주소를 지정합니다.
  (예: 다운로드·오픈채팅·설문 링크) 링크는 더 이상 STEP 1/2/3에 고정되지 않습니다.
- **문구·이미지·FAQ**: 제목·설명(줄바꿈 O)·이미지(파일 선택/파일명/URL)·FAQ 편집.
- **링크 복사 / 열기 / 내보내기**: 참가자 주소 복사, 미리 열기, `onboarding-data.js` 백업 내보내기.

> 기존에 시트/파일로 저장해 둔 과정은 열 때 자동으로 새 구조로 변환되어 그대로 유지됩니다.

## 과정 안내 메일 만들기

허브의 과정 카드에서 **메일** 버튼을 누르면, 그 과정 데이터로 발송용 HTML이 자동 생성됩니다.

1. 미리보기에서 **데스크톱 / 모바일** 폭을 전환하며 확인
2. **소스 복사** → 타스온 등 발송 도구의 HTML 편집기에 붙여넣기
3. 또는 **.html 다운로드** → `{과정코드}-mail.html`

포함되는 내용: 히어로(뱃지·제목·설명·일러스트·버튼), 교육 안내 그룹, 커리큘럼 표, 오시는 길, 하단 링크, 푸터.
제외: 사전 준비 체크리스트·FAQ·진행률(메일에서 동작하지 않는 요소).
커리큘럼이나 오시는 길이 꺼져 있는 과정은 해당 섹션이 자동으로 빠집니다.

### 메일은 웹과 다릅니다

메일 클라이언트는 브라우저가 아니라서, 페이지 HTML을 그대로 복사하면 깨집니다.
그래서 생성기가 별도로 **표 기반 레이아웃 + 인라인 스타일 + 600px 고정폭**으로 다시 만듭니다.
테마 색상은 CSS 변수가 아니라 실제 색상값으로 박히고, 일러스트는 SVG 대신 PNG로 교체됩니다.

### 배포 전 확인

- `onboarding-config.js` 의 `siteUrl` 이 실제 배포 주소와 같아야 합니다. **메일 속 이미지는 절대 주소로만 보입니다.**
- `mail-assets/` 폴더와 `igm-logo.png` 가 배포에 포함돼야 이미지가 뜹니다.
- 푸터 정보는 `mailFooterOrg` / `mailFooterAddress` / `mailFooterEmail` 로 바꿉니다.
- 수신거부 줄은 현재 빠져 있습니다. 필요해지면 `onboarding-mail.js` 의 `footerSection()` 안 주석 한 줄을 풀고
  발송 도구의 치환 태그를 넣으세요.
- 실제 발송 전 **Outlook 웹 / Gmail / 네이버메일 / 모바일**에서 한 번씩 테스트를 권합니다.

### 카카오맵 연동 (선택)

오시는 길에 실제 지도를 띄우려면:

1. [developers.kakao.com](https://developers.kakao.com) 로그인 → **내 애플리케이션 → 애플리케이션 추가하기**
2. 만든 앱 → **앱 키**에서 **JavaScript 키** 복사
3. 같은 앱 → **플랫폼 → Web → 사이트 도메인 등록**
   - 배포 주소(예: `https://내사이트.netlify.app`)를 등록
   - 로컬에서도 쓰려면 `http://localhost:5500` 등도 함께 등록
4. `onboarding-config.js` 의 `kakaoJsKey` 에 붙여넣기
5. 허브에서 과정 편집 → 오시는 길 → 주소 입력 → **좌표 찾기** 클릭 → 저장

> 키가 없거나 좌표를 저장하지 않으면 지도 대신 **"지도 보기" 링크 버튼**이 표시됩니다.
> 사이트는 정상 동작하므로, 키는 나중에 넣어도 됩니다.

### 화면 구성

- **메인**: 좌측 교육 안내 그룹(일정·장소·준비물 등), 우측 HERO + 오시는 길
- **사전 준비 사항**: 준비사항 카드가 가로로 나열되고, 카드마다 일러스트·절차 체크리스트·하단 버튼
- HERO(배지·제목 줄·강조·설명·일러스트)와 안내 그룹, 오시는 길 모두 허브에서 편집합니다

### 문구 줄바꿈
설명·항목·답변 입력칸에서 **Enter** 로 줄을 바꾸면 참가자 화면에 그대로 반영됩니다.

### 이미지 (세 가지 방법)
1. **파일 선택**(권장): 단계의 이미지 칸 옆 **파일 선택** 버튼 → 내 컴퓨터에서 이미지를 고르면
   자동으로 크기를 줄여 데이터에 **내장**합니다. 폴더에 파일을 넣거나 재배포할 필요가 없습니다.
2. **images 폴더 + 파일명**: `images` 폴더에 파일을 넣고 칸에 파일명(예: `step1.png`)만 적기.
3. **웹 주소**: `https://...` 이미지 주소 붙여넣기.

> 파일 선택으로 내장한 이미지는 용량이 커질 수 있어 자동으로 축소(최대 1200px)합니다.
> 아주 큰 이미지는 2·3번 방식을 쓰는 편이 데이터가 가볍습니다.

> ⚠️ **Apps Script 업데이트 필요**: 내장 이미지를 시트에 저장하려면 백엔드가 큰 데이터를
> 여러 셀에 나눠 저장해야 합니다. `apps-script.gs` 를 **최신 코드로 다시 붙여넣고**
> (배포 → 배포 관리 → 편집 → 버전: 새 버전 → 배포) 한 번 갱신하세요. 웹앱 URL은 그대로입니다.

## 배포

### Netlify (드래그 앤 드롭)
1. app.netlify.com → **Add new site → Deploy manually**.
2. 이 폴더 전체를 드롭.
3. 참가자에게는 `https://<사이트>/course.html?c=<slug>` 를 전달.

### GitHub Pages
1. 파일들을 저장소에 올린다(`index.html` 이 루트에 오도록).
2. **Settings → Pages** → Branch `main` / 루트(`/`).
3. 참가자 주소: `https://<계정>.github.io/<저장소>/course.html?c=<slug>`.

> 참가자에게 주는 링크는 항상 **`course.html?c=<slug>`**. `index.html`(허브)은 운영자 전용.
